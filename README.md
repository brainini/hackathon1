# 🎟️ TWOPICK (투픽) — 1인 해커톤 데모데이 투표

> **원픽은 너무 가혹하니까, 두 개 고르세요.**

수업 마지막 날, 각자 만든 서비스를 발표하고 서로 투표하는 **1인 해커톤 데모데이**용 웹서비스입니다.
학생은 자기 작품을 등록하고, 강사가 **"투표 시작!"** 을 누르면 **자기 작품을 뺀 2개 작품**에 티켓을 던집니다.
투표가 끝나면 프로젝터 화면에서 3위 → 2위 → 1위 순서로 결과를 발표합니다.

---

## 한눈에 보기

```
📝 작품 접수  ──▶  🎟️ 투표 진행  ──▶  🔒 투표 마감  ──▶  🏆 결과 발표
(학생 등록)       (강사가 시작)       (강사가 마감)       (무대에서 공개)
```

| 주소 | 누가 | 하는 일 |
|---|---|---|
| `/` | 모두 | 현재 진행 단계, 참가작 갤러리, 바로가기 |
| `/register` | 학생 | 작품 등록·수정 (이름, 프로젝트 이름, 소개, 스크린샷 1장, 아바타, PIN 4자리) |
| `/vote` | 학생 | 자기 작품을 뺀 작품 2개에 투표 (마감 전까지 수정 가능) |
| `/results` | 모두 | 결과 발표 후 순위·시상 확인 |
| `/stage` | 강사(프로젝터) | 접속 QR, 실시간 등록·투표 현황, 결과 발표 세리머니 |
| `/admin` | 강사 | 단계 전환, 참가자 관리, 설정, 데모 데이터, 초기화 |

투표 규칙
- 등록한 학생만 투표할 수 있고, 1인 1표(티켓 2장)입니다. 같은 작품에 2장을 줄 수 없고, 자기 작품에는 투표할 수 없습니다.
- 참가자가 2명뿐이면 티켓은 자동으로 1장이 됩니다. (티켓 수 = min(설정값, 참가자 수 − 1))
- 투표는 비밀입니다. 관리자도 "누가 누구를 찍었는지"는 볼 수 없고, 득표수와 투표 여부만 보입니다.
- 동점은 공동 순위로 처리합니다 (1위, 1위, 3위 …).

## 수업 당일 진행 매뉴얼

**수업 전 (5분)**
1. 배포된 사이트의 `/admin` 에 관리자 비밀번호로 로그인합니다.
2. **🧪 데모 데이터 넣기** 로 가짜 참가자를 만들어 투표 시작 → 마감 → `/stage` 발표까지 한 번 리허설합니다.
3. 리허설이 끝나면 **전체 초기화** (확인 문구 `초기화` 입력) 로 깨끗하게 비웁니다.

**수업 중**
1. 프로젝터에 `/stage` 를 띄웁니다. 화면의 QR 코드로 학생들이 접속합니다. (`F` 키: 전체화면)
2. 학생들은 `/register` 에서 작품을 등록합니다. 스크린샷은 캡처 후 **Ctrl+V** 로 바로 붙여넣을 수 있습니다.
3. 발표를 진행합니다.
4. `/admin` → **투표 시작!** (안전 덮개를 열고 누르는 버튼입니다.) 무대 화면에 카운트다운이 나옵니다.
5. 학생들은 `/vote` 에서 투표합니다. `/stage` 에서 투표율과 아직 투표하지 않은 사람을 실시간으로 볼 수 있습니다.
6. `/admin` → **투표 마감**.
7. `/stage` 에서 **🎤 결과 발표 시작** → `Space`/`→` 로 한 단계씩 공개합니다 (`←` 이전, `R` 처음부터, `M` 음소거, `F` 전체화면).
8. 마지막 화면의 **📢 모두의 화면에 결과 공개** (또는 `/admin` → 결과 공개) 를 누르면 학생들 화면에도 결과가 나옵니다.

> 💡 관리자 비밀번호를 여러 번 틀리면 같은 IP(같은 교실 와이파이)에서 관리자 로그인이 10분간 잠깁니다. **수업 시작 전에 미리 로그인**해 두세요.

**이럴 땐 이렇게**

| 상황 | 해결 |
|---|---|
| 학생이 PIN을 잊었어요 | `/admin` 참가자 목록 → **PIN 재설정** → 새 PIN을 알려줍니다 |
| 다른 기기에서 투표하고 싶어요 | `/vote` 에서 이름을 고르고 PIN을 입력하면 로그인됩니다 |
| 투표 시작 후에 지각생이 왔어요 | `/admin` → **이전 단계로** (접수) → 등록 → 다시 **투표 시작!** (이미 한 투표는 그대로 남습니다) |
| 오타·중복 등록 | `/admin` 참가자 목록에서 **수정** / **삭제** |
| 최하위 득표가 공개되는 게 부담돼요 | 기본값은 **시상대(Top 3)만 공개**입니다. 전체 순위는 설정의 "냉정 모드 🧊" 를 켜야 보입니다 |
| 결과를 기록해 두고 싶어요 | `/admin` → **CSV 내보내기** (엑셀에서 한글이 깨지지 않습니다) |

## 로컬에서 실행하기

```bash
npm install
npm run dev
```

- http://localhost:3000 에 접속합니다.
- 로컬에서는 Redis 없이도 동작합니다. 데이터는 프로젝트의 `.data/` 폴더에 저장됩니다.
- 관리자 비밀번호를 정하지 않으면 로컬에서는 `admin` 입니다. (배포 환경에서는 반드시 설정해야 합니다.)
- API 스모크 테스트: 서버를 켠 상태에서 `node scripts/smoke.mjs` (주의: 테스트 중에 데이터를 초기화합니다)

## Vercel에 배포하기

1. 이 저장소를 GitHub에 올립니다.
2. [vercel.com](https://vercel.com) → **Add New → Project** → 저장소를 Import 합니다. (프레임워크는 Next.js로 자동 인식됩니다)
3. 프로젝트의 **Storage** 탭 → **Upstash for Redis** (Marketplace) → 무료 플랜으로 만들고 이 프로젝트에 **Connect** 합니다.
   `KV_REST_API_URL`, `KV_REST_API_TOKEN` 환경변수가 자동으로 추가됩니다.
4. **Settings → Environment Variables** 에 추가합니다.
   - `ADMIN_PASSWORD` — 관리자 비밀번호 (**필수**)
5. **Deployments → Redeploy** 로 다시 배포합니다.
6. (권장) 지연을 줄이려면 Redis 리전과 **Settings → Functions → Region** 을 가까운 곳(예: 서울 `icn1`)으로 맞춥니다.

> Redis를 연결하지 않고 배포하면 데이터가 서버 메모리에만 저장되어 언제든 사라질 수 있습니다. 관리자 화면에 빨간 경고가 뜨니 꼭 연결하세요.

### 환경 변수

| 이름 | 필수 | 설명 |
|---|---|---|
| `ADMIN_PASSWORD` | 배포 시 필수 | `/admin` 로그인 비밀번호. 로컬에서 비워 두면 `admin` |
| `SESSION_SECRET` | 선택 | 쿠키·PIN 서명 키. 비워 두면 서버가 무작위 키를 만들어 Redis에 저장합니다. **학생 등록 후에 바꾸면 모든 PIN이 무효**가 되니 설정하려면 수업 전에 하세요 |
| `KV_REST_API_URL` / `KV_REST_API_TOKEN` | 배포 시 필수 | Upstash Redis (Vercel에서 Connect 하면 자동 설정) |
| `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` | 선택 | Upstash 콘솔에서 직접 만든 경우 위 대신 사용 |
| `KV_PREFIX` | 선택 | Redis 키 접두사 (기본 `twopick`). 반마다 다른 값을 쓰면 DB 하나로 여러 반을 운영할 수 있습니다 |

## 기술 구성

- **Next.js 16** (App Router, Cache Components) · **TypeScript** · **Tailwind CSS v4** · **motion** · **SWR**
- **Upstash Redis** — 참가자, 투표, 이미지를 저장합니다. 이미지는 브라우저에서 WebP로 압축해 올리고, `/api/images/[id]` 로 CDN 캐시와 함께 제공합니다.
- **실시간 갱신** — 각 화면은 약 3초마다 상태를 확인합니다. 바뀐 내용이 없으면 버전 번호만 비교하므로 Redis 명령을 1개만 씁니다.
  (30명 × 3시간 기준 약 10만 명령 → Upstash 무료 한도인 월 50만 명령 안에서 넉넉합니다.)
- 로그인 — 학생은 등록할 때 정한 PIN 4자리, 강사는 `ADMIN_PASSWORD`. 서명된 httpOnly 쿠키를 씁니다.

```
src/
  app/               페이지(정적 셸)와 API 라우트 (src/app/api/**)
  components/        ui(기본 부품) · brand(공용 브랜드 컴포넌트) · 페이지별 컴포넌트
  lib/types.ts       서버·클라이언트 공용 타입 (API 계약)
  lib/constants.ts   제한값, 이모지, 색상, 단계 이름
  lib/server/        저장소(Redis/파일/메모리), 인증, 검증, 투표·집계 로직
scripts/smoke.mjs    API 전체 흐름 스모크 테스트
```
